# 30 天內容日曆規格

## 欄位

| 欄位 | 必填 | 說明 |
|---|---|---|
| `date` | 是 | `YYYY-MM-DD`，由早到晚，不重複 |
| `pillar` | 是 | 內容支柱，要在定位卡裡有 |
| `topic` | 是 | 這一天講什麼，一句話 |
| `format` | 是 | `Reel`、`輪播`、`限動`、`貼文`、`直播`、`長影片`、`Threads`、`Email`、`長文` |
| `route` | 是 | 製作路徑：`自己錄`、`AI聲音`、`AI數字人`、`圖文`、`文字`（Threads、Email、長文通常用 `文字`） |
| `hook` | 是 | 開頭鉤子，前 3 秒或第一頁要說什麼 |
| `goal` | 是 | `認識`、`信任`、`轉換`、`名單` |
| `cta_keyword` | goal 為「轉換」「名單」時必填 | 留言關鍵字，6 字內、不含空白 |
| `script` | 否 | 重點或腳本，可為路徑 |
| `source` | 否（但建議填） | 來源：素材卡 id（如 `["M03"]`）或錄音段落 id（如 `["B03"]`）。加 `--materials` 檢查時，沒有來源的項目會被列出 |
| `likeness_ok` | 路徑為 `AI數字人` 時必須為 `true` | 確認為本人肖像或已取得同意 |
| `status` | 是 | `待辦`、`已錄`、`已剪`、`已排程`、`已發布` |
| `notes` | 否 | 備註 |

## 配比建議（可調整，不是定律）

| 項目 | 建議 |
|---|---|
| 內容支柱 | 3 到 5 個，輪流出現，同一支柱不連續超過 3 天，單一支柱不超過一半 |
| 導向轉換／名單 | 約 15% 到 30%。太少沒導回服務，太多像一直在推銷 |
| 格式 | 依使用者的平台與時間：每週 2 到 3 支影片＋其餘圖文與限動，比天天影片可持續 |
| 製作路徑 | 依使用者選擇；建議新手以「自己錄」為主，避免一次導入太多新工具 |

## 每週節奏的例子（僅供參考）

| 週內 | 內容 |
|---|---|
| 週一 | 迷思破解（輪播） |
| 週三 | 外食怎麼選（Reel） |
| 週五 | 生活小習慣（Reel）或導向名單的內容 |
| 週日 | 本週回顧或直播 |

## 路徑的取捨（說明給使用者聽）

| 路徑 | 優點 | 限制 |
|---|---|---|
| 自己錄 | 最有個人感，可接語剪室剪輯與雙語字幕 | 要花時間錄 |
| AI聲音 | 不用出聲 | 目前尚未提供自動化；需使用本人聲音或已授權的聲音 |
| AI數字人 | 不用出鏡 | 目前尚未提供自動化；肖像授權、平台標示要求；品質與中文口型需先實測 |
| 圖文 | 製作快，沒有肖像與素材授權問題 | 由 `carousel-maker` 排版，版型有限，不含照片與插圖 |

## 檢查指令

```bash
python "${CLAUDE_PLUGIN_ROOT}/skills/content-calendar/scripts/calendar_tools.py" check calendar.json
```

| 類別 | 處理方式 |
|---|---|
| 錯誤 | 一定要修 |
| 警告 | 逐項判斷，修或向使用者說明保留原因 |
| 用語提示 | **只是提示，不是法律判斷**。逐項告訴使用者，請他或專業人士確認 |

## 誠實原則

- 素材不夠 30 天，就說不夠，並告訴使用者缺什麼。
- 不編造數據、案例、見證或證照。
- 不寫「保證」「一定」「百分之百」之類的用語，也不替使用者寫這類承諾。

## 文字格式的取捨

| 格式 | 適合 | 提醒 |
|---|---|---|
| Threads | 短觀點、迷思澄清、一句話的經驗 | 字數短，一則一個重點 |
| Email | 與已有名單的人深入說明、整理成清單 | 需有名單與取得同意的寄送機制；寄信規範請專業人士確認 |
| 長文 | 完整的做法、經驗故事 | 結構要清楚，並保留使用者自己的口吻 |

這些格式都不是固定產出數量。**數量取決於使用者真正講過的素材**，不夠就說不夠。
