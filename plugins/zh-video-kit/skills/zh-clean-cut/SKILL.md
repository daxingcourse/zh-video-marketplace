# 中文口播清理剪輯

輸入一支中文口播影片，輸出剪乾淨的 MP4，以及時間軸對齊的 `transcript.cut.json`。

**原則：先出計畫、再審核、最後才剪。** 不直接動手剪，因為「就是」「然後」「對」在不同句子裡可能是贅詞，也可能是正文。

## 環境

與 `zh-bilingual-captions` 共用：ffmpeg 在 PATH、`pip install faster-whisper opencc-python-reimplemented`。

## 流程

1. **轉錄**：用 `${CLAUDE_PLUGIN_ROOT}/skills/zh-bilingual-captions/scripts/transcribe_zh.py` 產生 `work/transcript.json`。先讀一遍，亂碼或靜音處幻聽就停下來回報。

2. **取得影片長度**
   ```bash
   ffprobe -v error -show_entries format=duration -of csv=p=0 input.mp4
   ```

3. **分析，產出計畫**
   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/skills/zh-clean-cut/scripts/analyze.py" work/transcript.json --duration <秒數> -o work/ --audio work/audio.wav
   ```
   會產生：
   - `cut_plan.json`：所有候選剪點。`auto: true` 會剪，`auto: false` 待審核。
   - `sentences.txt`：逐句清單，供判斷重錄。

   偵測內容：

   | 類型 | 判斷 | 預設 |
   |---|---|---|
   | silence | 詞間停頓 > 0.5 秒，只剪中間，兩側各保留 0.15 秒；頭尾靜音一併修短 | 自動 |
   | filler (hard) | 嗯、呃、欸、喔、啊 等純語助詞 | 自動 |
   | filler (soft) | 那個、就是、然後、對、其實 等 | **待審核** |
   | stutter（2 字以上重複） | 「我想我想」只剪前一份 | 自動 |
   | stutter（單字重複） | 「我我」；排除「看看、謝謝」等正常疊字 | **待審核** |
   | 疑似贅詞（「嗯」被聽成「恩」） | 單獨成詞的「恩」 | 自動 |
   | 疑似贅詞（「呃」被聽成「二」「額」「餓」「阿」） | 單獨成詞才列入 | **待審核** |
   | retake（重錄） | 腳本不偵測 | 由你判斷 |

4. **審核與補充（這一步由你這個 Claude 做，不能略過）**
   - 打開 `cut_plan.json`，逐一檢視 `auto: false` 的項目，依 `reason` 裡的前後文判斷：是贅詞就改 `auto: true`，是正文就保持 false。
   - 讀 `sentences.txt` 找**重錄**：同一個意思連續講了兩三次（前面幾次語氣中斷、重頭開始、說錯後說「不對」「重來」）。保留**最後、最完整**的一次，把前面幾次的時間範圍加進 `cuts`：
     ```json
     {"id": 99, "start": 12.4, "end": 15.1, "kind": "retake", "auto": true, "text": "（被取代的那句）", "reason": "第 5 句為重錄，保留第 6 句"}
     ```
   - 有爭議的剪點不要硬剪，寫進回報給使用者決定。
   - 剪完後句子的語意要連得起來；若剪掉一段會讓前後句變得不通順，就不要剪。

5. **先看預覽數字**
   ```bash
   python "${CLAUDE_PLUGIN_ROOT}/skills/zh-clean-cut/scripts/render_cut.py" input.mp4 work/cut_plan.json work/transcript.json -o output.mp4 --dry-run
   ```
   確認「剪掉多少秒、保留幾段」合理（口播通常剪掉 10～30%；超過 40% 要再檢查）。

6. **渲染**：拿掉 `--dry-run` 再跑一次。會同時輸出 `transcript.cut.json`。

7. **驗收（必做）**
   - `ffprobe` 確認影片與音訊長度大致相同（差距 < 0.1 秒）。
   - 在幾個接點前後各截一張圖，並請使用者聽接點是否自然。我們無法替使用者聽，所以要如實說「接點需要你聽過確認」。
   - 需要上字幕時，接著用 `transcript.cut.json` 跑 `zh-bilingual-captions` 的第 2 步之後的流程（斷句、翻譯、燒錄），**不要用舊的 transcript.json**，時間軸已經不同。

## 可調參數

- `--gap 0.5`：多長的停頓才剪。節奏快的短影音可調 0.35；講課、需要停頓感的內容調 0.8。
- `--keep 0.15`：剪停頓後保留的呼吸空間。太小會有「被吃掉」的感覺。
- `fillers.json`：自行增減贅詞表。每個人口頭禪不同。

## 波形校正（重要）

Whisper 的詞時間戳常有 0.1～0.4 秒誤差（實測「大家好」結尾被標早了 0.36 秒，直接剪會吃掉「好」）。所以：
- **停頓**由音訊波形直接偵測，不看詞時間戳。
- **其他剪點**（贅詞、口吃、重錄）在渲染時貼齊到最近的真實靜音處（`render_cut.py --audio`）。
- 邊界落在**連續語流**（附近找不到靜音）的剪點，分析時會自動降為「待審核」並標註「可能吃字」。**寧可漏剪，不要吃字。** 請用 `ffplay -ss <秒-0.5> -t 3 input.mp4` 聽過再決定；你決定剪的話，渲染時會貼齊到最低能量處，但不保證不吃字。
- 沒給 `--audio` 時會退回詞時間戳並印出警告，誤差較大。

## 已知限制

- **Whisper 會自動「修飾」口語**：口吃、重複的字常被它直接省略（實測「我我會」只留一個「我」），贅詞也可能被聽成同音字。轉錄時已用提示詞要求保留，但**不保證**，逐字稿看不到的贅詞，這套流程就剪不到。若成品仍有明顯口誤，請用 `--remove` 手動加剪點。
- 靜音判斷依據是**逐字稿的詞間隔**，不是音訊波形。Whisper 的時間戳偶爾不準，貼字稿邊界剪時可能吃到字尾，必要時調高 `--keep`。
- 贅詞若與相鄰字被辨識成同一個 token（如「嗯我」），為安全起見會降為待審核，不自動剪。
- 只處理單一音視訊來源。多段素材請先分別處理。
- 剪點處用 10 毫秒音訊淡入淡出避免爆音，但不做視覺轉場，畫面會有跳接感；口播本來就是跳接風格。想遮掉跳接可另外加 B-roll 或放大裁切，那是別的流程。

## 測試狀態

- 已驗證（合成語音，Windows，CPU）：完整流程「轉錄 → 分析 → 審核 → 剪輯 → 重新轉錄驗證」。30.4 秒剪成 18.8 秒，剪後影片重新轉錄，嗯、二、重複的「我想」都消失，最長停頓 0.78 秒；「看看」不誤剪；soft 詞（就是）不自動剪；剪後逐字稿時間軸可直接接字幕流程。
- **尚未驗證**：真人口播的接點聽感（我聽不到，需要你聽）；真人錄音的贅詞偵測率；Whisper 在真人語速下的時間戳精度。
